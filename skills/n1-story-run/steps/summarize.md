# Summarize

Posts a technical summary comment on the story ticket and marks the story done.

## 1. Idempotency

If `GET_COMMENTS_OP` is set, call `mcp__${TRACKER_MCP}__${GET_COMMENTS_OP}` for `STORY_ID` (Jira: include `cloudId`). Search the returned comments for any whose body contains `N1 Story Summary — ${STORY_ID}`. If found: print "Summary already posted." and go to §4.

## 2. Collect per subtask

From `## Plan` in `story.md`, collect rows whose Status is `merged`. For each such row: `KEY`, `REPO`, `SUB_HOME` (N1 Home column), `SERVICE`.

For each collected row:

**overview.md** — read `$SUB_HOME/memory/$KEY/overview.md`:
- Extract frontmatter fields: `pr_url`, `branch`, `docs_updated`.
- Extract the `## Decision Ledger` table; keep at most 2 rows marked `[auto]` whose Reason is non-trivial (not "default" / "n/a").
- Extract QA status if a `## QA` or `qa_status` field is present.

**implementation.md** — read `$SUB_HOME/memory/$KEY/implementation.md`:
- Take the first `## Summary` section (lines until the next `##`). If absent, take the first 15 non-empty lines.

**PR metadata** — run in the subtask's repo:
```bash
cd "$REPO" && gh pr view "$PR_URL" \
  --json title,url,state,mergedAt,additions,deletions,changedFiles,files \
  -q '{title,url,mergedAt,additions,deletions,changedFiles,files:[.files[].path]}' \
  2>/dev/null
```
On failure (non-zero exit or empty output): note "PR metadata unavailable" and use `pr_url` and title from `overview.md` only. Set `additions`, `deletions`, `changedFiles` to `?`.

**CI status** — run:
```bash
cd "$REPO" && gh pr checks "$PR_URL" --json name,state 2>/dev/null
```
Parse: if all entries have `state: SUCCESS` -> `all passed`; else count failures -> `<n> failed`; on error -> `unavailable`.

**Repo label**:
```bash
REPO_LABEL=$(cd "$REPO" && git remote get-url origin 2>/dev/null || echo "$REPO")
```

## 3. Compose and post

Group rows by Service in Plan table order. Build the comment body as follows (fill in values from §2; do not include lines whose data is entirely absent):

```
N1 Story Summary — <STORY_ID>

## <SERVICE> (<REPO_LABEL>)
### <KEY>: <title> — <PR_URL> (merged <mergedAt date, date part only>)
- What: <3–6 bullet points derived from implementation.md summary and changed file paths: components, endpoints, schema, config>
- Files: <changedFiles> changed (+<additions>/−<deletions>); key paths: <up to 5 paths from files list>
- Tests: QA <qa status from overview if present>; CI <ci summary>
- Notes: <up to 2 ledger decisions — omit this line entirely when none>

[next subtask in same service group...]

## <NEXT_SERVICE> (<REPO_LABEL>)
...

---
Subtasks completed before this run: <done-before-run keys, or none>
Skipped: <skip-status keys, or none>
Run: started <frontmatter started>, finished <now>, <n merged subtasks> subtasks, models: sonnet ×<count>, opus ×<count>

*Generated by N1 story orchestrator*
```

Compute `now`:
```bash
NOW=$(date -u +%Y-%m-%dT%H:%M:%SZ)
```

Compute model counts from `## Plan` Model column across all rows that were `pending` at the start (exclude `done-before-run` and `skip`).

**Jira checkbox stripping:** when `TRACKER_TYPE` is `jira`, replace all occurrences of `- [ ] ` and `- [x] ` with `- ` in the composed body before posting.

Post the comment on `STORY_ID` via `mcp__${TRACKER_MCP}__${COMMENT_OP}`:
- Jira: fields `cloudId`, `issueIdOrKey` (`STORY_ID`), `commentBody`.
- YouTrack: fields `issueId` (`STORY_ID`), `text`.

On transient failure (network / 5xx), retry twice with a brief pause before giving up. On persistent failure: append to `## Escalations` in `story.md`, set `step: paused`, print error, **STOP**.

## 4. Finish

```bash
n1_write_frontmatter "$STORY_MEM/story.md" step done
n1_write_frontmatter "$STORY_MEM/story.md" finished "$(date -u +%Y-%m-%dT%H:%M:%SZ)"
```

Print: "Story summary posted on <STORY_URL>. Transition <STORY_ID> when ready."

Story status in the tracker is **not** changed by this step.
